# 三分钟讲解

**问题**：同一财年会在多份年报中出现。按 API 的 `fy` 筛选，或用今天最新数据分析过去，会混入比较期错误或未来信息。

**做法**：明确实际财年与申报截止日，按 start/end 取数，再选当时最新的申报。指标记录公式、输入角色、fact ID 和原始申报链接。

**演示**：切换 2024-10-31 和 2024-11-01，观察 FY2024 从缺失到可用；查看 `fy=2024` 的 FY2023 比较期记录；展示 371 天与 364 天的两个财年，以及 FCF 的计算和来源。

**验证**：独立 SQL 查询逐条对照。修改指标 CSV 并更新哈希，语义复算仍拒绝。测试覆盖未来信息、季度混入、单位不匹配、同日冲突、缺失值与零分母。

追问要点：`fy` 不能代替事实本身的期间；缺失不等于零；增长没有按周数归一化；哈希验证一致性而不证明来源真实性；扩展到其他公司需要补充概念、单位与会计政策映射。

简历可写“构建申报截止日财报快照和指标血缘工具，使用公开年报摘录验证 53 周财年、比较期选择与独立 SQL 对照”。不要写完整 XBRL 覆盖、实时生产服务、信用评级或投资收益。
